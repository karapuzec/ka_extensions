4.1.1.30 (not released)
- Mail: inline images in emails. \extension\ka_extensions\Mail::addInlineImage($filename, $name = '') (and the same method of the OpenCart mail object) adds an image for the html part; it is shown by <img src="cid:<cid>"> where the cid is returned by the static \extension\ka_extensions\Mail::generateCid($filename) ('ka-<md5 of the full path>.<extension>', the same for every call). $name is the file name in the email, basename($filename) when empty. The type (png, jpeg, gif, webp) is detected from the file; another file is added as a regular attachment and the method returns false. The patched mail adaptors (mail/mail.php.xml, mail/smtp.php.xml) send inline images as image/* parts with 'Content-Disposition: inline' inside multipart/related together with the text and html parts, other attachments stay in multipart/mixed; an email without an html part gets them as inline image/* parts of multipart/mixed. Emails without inline images are built exactly as before (checked on OpenCart 3.0.0.0, 3.0.4.0, 3.0.5.1 with the mail and smtp engines). A module can check method_exists($mail, 'addInlineImage') and call addAttachment() with older libraries. The kamod cache has to be rebuilt after the update. The logo and the 'images are enclosed' setting are not changed. See docgen/guides/mail.rst.

- Notifications (\extension\ka_extensions\Notifications): a bell in the admin header next to the Kamod Health Status icon (kamod child of common/header and the header.twig kapatch of the library). add($code, $text, $ttl = 0) for the logged in administrator (for all administrators when there is none, e.g. in the catalog), addForAll($code, $text, $ttl = 0) for all administrators, remove($code), get($code). $ttl in seconds, 0 = until closed. The bell is shown to administrators with access to Extensions > Ka Extensions when they have notifications; the text is escaped; the cross deletes a notification by POST (extension/extension/ka_extensions/deleteNotification, modify permission of Ka Extensions). New table ka_notification (created on the Ka Extensions page or on the first add()). en-gb and ru-ru strings. See docgen/guides/notifications.rst.
- HiddenSettings (\extension\ka_extensions\HiddenSettings): hidden values of a module in the admin area and in the catalog, get($ext_code, $key, $default = null), set($ext_code, $key, $value) and increase($ext_code, $key, $add = 1). The storage is the same as of getConfigHidden()/setConfigHidden() (group '<ext_code>_hidden', keys '<ext_code>_hidden_<key>', arrays as JSON). set() writes one key instead of the whole group, increase() is one UPDATE value = value + N (a missing value is inserted once under a named lock), so parallel requests do not lose values. getConfigHidden()/setConfigHidden() of the admin setting model are wrappers of it now. See docgen/guides/upgrading_modules.rst.
- TraitDBFilter (DBProxy): removeFilter() removed all filters of the class, a nested method removing its filter also removed the filter of the calling method (e.g. several modules extending one model method). Fixed: setFilter() returns the filter id, removeFilter($id) removes only that filter, removeFilter() without the id removes only the last filter of the current class. Existing calls work as before; the recommended use is $id = setFilter(...) and removeFilter($id) in a 'finally' block.
- Forms: validateField() of a 'number' field returned true after the 'Minimum value is %s' / 'Maximum value is %s' error, a child class checking more could go on and replace the error. Fixed: it returns false. An empty value of a non-required 'number' field is not checked against min_value/max_value any more (a minimum above zero gave an error).
- Settings page (ControllerSettings): a validation error of a module without its own text was shown as the raw key 'error_field_is_empty'. Fixed: the page loads the library common language file before the module files (a module text still wins). New ru-ru texts of the field validation ('Поле не заполнено', minimum, maximum, not a number) in admin and catalog, the 'number' validation texts are in en-gb too.
- Extensions > Ka Extensions: a module installed without a stored version (0.0.0.0) showed the orange 'Files: ..., installed: 0.0.0.0' text under its version. Now nothing is shown under the version in this case, the hint stays in the tooltip of the 'Refresh' button. The Version column is wider (15%), the Name column is 45%.
- Module upgrade: Extensions > Ka Extensions shows a yellow 'Refresh' button next to an installed module when $extension_version of its files is greater than the installed version, with the hint 'Files: <version>, installed: <version>' (en-gb and ru-ru). The button (POST only, the modify permission of Ka Extensions) calls the new upgradeExtension($from_version, $to_version) of the module installer; on success the new version is stored, the kamod cache is marked for a rebuild and the module page gets the permissions, on failure the installed version and the button stay. By default upgradeExtension() calls install(), a module overrides it for migrations. A module without $extension_version gets no button. See docgen/guides/upgrading_modules.rst.
- Installation: the version of the module ($extension_version) is stored on installation as the hidden value 'version' of the module. A module installed by an older library has no stored version, it is 0.0.0.0 (the 'Refresh' button is shown once).
- Admin setting model (kamod child of model/setting/setting): getConfigHidden($ext_code, $key) and setConfigHidden($ext_code, $key, $value) for hidden values of a module (the installed version, counters). They are stored by the OpenCart getSetting()/editSetting() in the group '<ext_code>_hidden' under the keys '<ext_code>_hidden_<key>', other hidden values of the module are kept, saving the settings page does not touch them. A missing value is null.
