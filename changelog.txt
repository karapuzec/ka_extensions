- QB hooks: new trait TraitQB with getQB($table = '', $alias = '') and onQB($table, $callback, $sort_order = 0) (returns a subscription id), offQB($id) (removes it, an unknown id is ignored), used by the base Model and Controller of the library; a developer can use it in other classes too, e.g. a kamod child of a standard OpenCart model: class ModelCatalogProduct extends \ModelCatalogProduct { use \extension\ka_extensions\TraitQB; }. getQB() returns 'new QB()' with from($table, $alias) when the table is given and the callbacks of onQB() for the table and '*' (all), use it instead of 'new QB()' so other modules can extend the queries: they subscribe with onQB() in a kamod child of the class (constructor or onLoad()) or override getQB(). The callbacks are kept by the object (protected $qb_hooks, no static storage), the ones of the table first, then '*', by sort order and subscription order. Usually a module subscribes for a while in a method of a kamod child: $id = $this->onQB('product', function($qb) { $qb->where('p.ka_hidden', 0); }); $result = parent::getRecords($filter); $this->offQB($id); getQB() copies the current callbacks into the QB object, so a QB made while the subscription was active keeps the callback after offQB(), QB objects made after offQB() do not get it. QB: the table key is the table of the first from() call (QB::getTable(), joins do not change it, queries of several tables in from() are not supported by the hooks), QB::addHook($callback) - a callback called with the QB object at the start of every getSql() call (also query(), ModelRecordset::getRecordsTotal(), the QB objects inside fromUnionAll() run their own hooks once per getSql() of the outer one), so it may run several times per object. 'new QB()' works as before. Docs: docgen/guides/code_design_guidlines.rst. Tests: unit QBHooksTest, integration QbHooksTest (group smoke).

It wraps jbroadway/urlify 1.2.5 with voku/portable-ascii 2.1.1 and voku/stop-words 2.0.1, added to system/library/extension/ka_extensions/vendor (with their licenses, loaded without composer, PHP 7.2+). The language code ('ru', 'ru-ru') selects the transliteration rules; Ukrainian letters missing in the Ukrainian table are converted by the Russian rules.
- Forms: a 'text' or 'textarea' field can have 'max_length' (characters, e.g. the size of its database column). A longer posted value fails validation with the new language string error_field_too_long (admin and catalog, en-gb and ru-ru).
- Installation: permissions of the extension pages were added to the user group on every installation, a reinstalled module had its routes in the group lists several times. Fixed: a permission is added only when the group does not have it yet. Existing duplicates are removed when the user group is saved.
- Forms: a 'checkboxes' field (a list of checkboxes) could not be saved with all boxes unchecked, the old value was kept because unchecked boxes are not posted. Fixed: a submitted form without the field saves an empty list.
- ControllerList: delete() and deleteRecord() work by POST requests only, a GET request (e.g. a link) deletes nothing and shows the permission error. A delete link in a list template has to be replaced with a button posting to the same url.
- Language: the permission error of the library pages (e.g. a refused GET delete of ControllerList) was shown as the raw key 'error_permission' when the module language file did not define it. Fixed: error_permission is in the library common language file (en-gb, and a new ru-ru file); a module's own error_permission still wins.
- QB: orderBy($order, $after) and groupBy($groupBy, $after) dropped the value (wrong argument order of Arrays::insertAfterKey()). Fixed: the value is put after $after, at the end when $after is not in the list. Several from() tables are separated with commas.
- kamod: a kapatch for a newer or another major kamod version was skipped, but the patched file was written empty. Fixed: the file keeps its contents.
- kamod: the log (kamod.log) had the month name instead of the hour in the time. Fixed.
- Pagination: without the 'limit' parameter the OpenCart 3 setting 'Default Items Per Page (Admin)' (config_limit_admin) was ignored and 20 was used. Fixed.
- Model: the deprecated getNamespace() used an undefined variable for a class without a namespace (a warning). Fixed: an empty namespace is returned.
- Forms: validation of fields. A required field of spaces passed; a required 'checkboxes' field posted as an empty list gave a TypeError; a non-numeric value of a 'number' field with min_value/max_value passed the limits (now 'The value must be a number'); initFields() of no fields returned null instead of an empty array. Fixed.
- Forms (ControllerForm): the raw POST was saved. An unchecked checkbox kept its old value, a 'checkboxes' field with all boxes unchecked kept the old list. A posted primary key was trusted when the url had none: a new record form updated the posted record. Fixed in the new protected getPostedRecord(): unchecked boxes are saved as '0' / an empty list, the primary key is taken from the url only.
- Form fields: the field templates (common/fields/*.twig, admin and catalog) printed values without escaping (OpenCart 3 Twig has autoescape off), a quote broke an input and HTML in a value was output as is. Fixed: values, placeholders and option values are escaped with the new Twig filter ka_escape (htmlspecialchars without encoding existing entities again, so values stored html-escaped by OpenCart are shown as before). Labels, errors and 'plaintext' fields are printed as before.
- Settings page template: the form posted to an empty 'action' (the controller sets 'action_save'), Enter in a field submitted to the current url. Fixed: the form uses action_save ('action' still wins when a module sets it).
- ControllerSettings: for a vendor other than 'ka_extensions' the settings page saved the values under '<vendor>_<ext_code>', but install() stored the default values and uninstall() deleted the settings under '<ext_code>'. The defaults did not reach the group of the page (OpenCart skips keys not starting with the code) and uninstallation left the saved values. Fixed: one protected getSettingCode() ('<ext_code>' for vendor 'ka_extensions', '<vendor>_<ext_code>' for others) is used for saving and installation (the settings are not deleted on uninstallation any more, see above). Old rows stored under '<ext_code>' by older versions are not removed automatically.
